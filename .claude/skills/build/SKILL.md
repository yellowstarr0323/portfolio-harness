# PDF 만들기 (build)

**먼저 읽는다**: `../../../rules/principles.md`(특히 "우선순위", "중요한 것들").

## 입력
- 기록: `portfolio/profile.md`, `portfolio/projects/*.md`, `portfolio/sources/`
- 디자인: `portfolio/design.md`(시안을 고름) 또는 `portfolio/reference.md`(레퍼런스대로)

## 1. 내용 정하기
- 프로젝트마다 무엇을 앞에 둘지 원칙의 우선순위로 정한다: 문제 해결 → 결과·성과 → 역할·기여 → 판단 → 설명 → 기술 스택.
- 문제 해결 경험은 "문제 → 원인 → 판단 → 해결 → 결과 → 배운 점" 중 기록에 있는 것만으로 쓴다. 없는 단계를 채우지 않는다.
- 기록에 없는 수치·사실은 쓰지 않는다. `(모름)`인 값은 빼고 쓴다.
- `portfolio/review/existing-review.md`가 있으면(기존 포트폴리오에서 시작) 그 `[수정]` 지적을 처음부터 반영해서 쓴다. 기록에 없는 사실이 필요한 지적은 반영하지 않는다.
- 레퍼런스가 있으면 `reference.md`의 쪽 구성·블록 순서를 따른다. 레퍼런스 칸에 맞는 기록이 없으면 칸을 비우지 말고 뺀다.

## 2. 문장
- 본문은 문어체(…했다 / 명사형 종결). **사용자 말투(…했어, …했음, …거든요)를 그대로 옮기지 않는다.**
- 한 문장에 한 가지 사실. 주어가 누구인지 분명히(팀이 한 일과 본인이 한 일을 섞지 않는다).
- 수치는 측정 조건과 같이 쓴다. 조건이 없는 수치는 "약", "체감" 같은 말로 부풀리지 말고 기록 그대로.

## 3. HTML
- 파일: `portfolio/out/index.html`, 스타일은 같은 폴더(`style.css`), 이미지는 `portfolio/images/`에서 `portfolio/out/assets/<슬러그>/`로 복사해 쓴다.
- **프로젝트마다 로고와 프로젝트 화면을 넣는다.** 로고는 프로젝트 첫머리(이름 옆), 화면은 1장 이상 본문에. 시작 전에 `python3 <이 스킬 디렉터리>/../interview/scripts/check_images.py portfolio`가 `모두 있음`인지 확인하고, 빠졌으면 build를 멈추고 사용자에게 이미지를 부탁한다.
- **A4 한 장 = `<section class="sheet">` 하나.** `.sheet { width: 210mm; height: 297mm; overflow: hidden; box-sizing: border-box; }`, `@page { size: A4; margin: 0; }`. 쪽 사이 넘김은 `.sheet { page-break-after: always; }`.
- 링크는 `<a href="https://…">`(절대 주소)로 감싼다.
- 디자인은 `design.md` 또는 `reference.md`의 색·글꼴·크기·배치를 그대로 쓴다.

## 4. PDF
```bash
python3 <이 스킬 디렉터리>/scripts/make_pdf.py portfolio/out/index.html portfolio/out/portfolio.pdf
```
- `넘침: n쪽`이면 그 쪽 내용을 줄이거나 다음 쪽으로 옮기고 다시 돌린다. 글자를 8pt 아래로 줄여서 맞추지 않는다.
- `이미지 깨짐`이면 경로를 고친다.
- 통과하면 PDF 첫 쪽과 프로젝트 첫 쪽을 직접 열어 글자가 겹치거나 잘린 곳이 없는지 본다. PDF를 바로 볼 수 있는 파일 읽기 도구(Claude Code의 Read)가 없으면 `pdftoppm -png -r 100 -f <쪽> -l <쪽> <PDF> <출력 이름>`으로 쪽을 PNG로 만들어 연다(`portfolio/out/pages/`).

## 5. 리뷰와 수정 반복 (loop, 최대 3회)

`portfolio/review/loop.md`에 회차와 사용자가 그대로 두기로 한 지적(거절 목록)을 남긴다. `state.md`에는 `loop: <회차>/3`.

**한 회차:**
1. **리뷰**: `portfolio-reviewer` 서브에이전트를 띄운다(Claude Code는 Agent 도구, Codex는 같은 이름의 custom agent). 프롬프트에는 **PDF 절대 경로만** 넣는다. 인터뷰 내용, 기록, 의도, 앞 회차 결과, 거절 목록을 넘기지 않는다(면접관처럼 PDF만 보고 판단해야 한다). 결과를 `portfolio/review/portfolio-reviewer-<회차>.md`에 그대로 저장한다.
2. **인용 확인**: 지적이 인용한 문장이 PDF에 실제로 있는지 확인한다. 먼저 `pdftotext` 글에서 공백·줄바꿈을 빼고 찾는다. 못 찾으면 버리기 전에 그 쪽을 직접 열어(Read, 없으면 위 `pdftoppm` PNG) 본다 — 이미지·도표 속 글자나 줄이 갈린 글은 `pdftotext`에 안 나온다(10-12: 이미지 속 "CONTRIBUTION Design 100%", 다이어그램 속 오탈자 지적이 이렇게 버려질 뻔했다). 눈으로 봐도 없는 인용의 지적만 버린다.
3. **거절 걸러내기**: 거절 목록과 같은 지적(같은 기준, 같은 내용)은 버린다. 사용자에게 다시 보여주지 않는다.
4. **끝 조건**: 남은 지적이 0개면 loop를 끝낸다("면접에서 물어볼 질문"은 세지 않는다).
5. **[수정] 지적**: 묻지 않고 고친다. 사실(누가·무엇을·얼마나)을 바꾸거나 기록에 없는 내용을 넣는 수정은 하지 않는다 — 그런 지적이면 [질문]으로 돌린다.
6. **[질문] 지적**: 전부 한 번에, 존댓말로 요약해서 묻는다. 지적마다 무엇이 부족해 보이는지 한 줄 + 질문 한 줄. 맨 끝에 "고치지 않을 항목은 '그대로 둘게요'라고 적어 주세요"를 붙인다. [질문]이 없으면 묻지 않고 다음 단계로 간다.
7. **반영**: 답은 기록(`portfolio/profile.md`, `portfolio/projects/`)에 `(출처: 사용자)`로 먼저 적고 HTML을 고친다. "그대로 둘게요"라고 했거나 답하지 않은 질문은 거절 목록에 넣는다. 모른다고 한 값은 `(모름)`으로 적고 거절 목록에 넣는다.
8. **다시 만들기**: 4의 make_pdf를 다시 돌려 통과시킨다. 고친 것([수정]으로 알아서 고친 것 포함)을 2~3줄로 알린다.

3회차의 8까지 끝나면 리뷰를 한 번 더 돌려 끝 보고용 점수만 얻는다(이때는 묻지도 고치지도 않는다). 3회 안에 끝 조건으로 끝났으면 그 회차의 리뷰가 마지막 점수다.

## 6. 끝나면
`portfolio/state.md`의 `stage: done`을 적고 start의 "끝 보고"를 한다.
- **PDF 전송은 하지 않는다.** 리뷰까지 끝난 최종 PDF는 턴 끝 훅(`.claude/hooks/send_on_done.py`)이 Discord로 자동으로 보낸다. 사용자에게 묻거나 알리지 않고, `upload.py`를 부르지 않고, 끝 보고에 전송 이야기를 쓰지 않는다. 훅이 최종본을 알아보도록 `stage: done`과 마지막 리뷰 파일 저장만 빠뜨리지 않는다(리뷰 파일은 마지막 PDF보다 나중에 저장돼야 한다). 끝 보고에 회차별 총점 변화, 마지막 리뷰의 한 줄 판단, 남은 지적(거절한 것 포함), "면접에서 물어볼 질문"을 넣는다.

## 아직 없는 검사
기록에 없는 수치가 본문에 들어갔는지, 사용자 말투가 본문에 남았는지, 링크가 실제로 열리는지는 스크립트로 검사하지 않는다(위 "1. 내용 정하기"·"2. 문장" 규칙과 리뷰어의 6번 기준(오류·모순)만 있다).
