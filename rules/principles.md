# 제품 맥락

## 서비스

이 서비스는 학생이 자신의 학업, 프로젝트, 수상, 활동, 기술 등의 정보를 입력하면 취업용 포트폴리오를 생성해주는 서비스다.

단순히 정보를 나열하는 이력서 생성기가 아니라, 학생이 가진 경험에서 강점과 문제 해결 과정을 찾아내고 이를 채용 담당자가 이해하기 쉬운 포트폴리오로 구성하는 것을 목표로 한다.

## 대상 사용자

* 주 사용자는 학생이다.
* 사용자는 자신의 경험을 전문적으로 표현하는 데 익숙하지 않을 수 있다.
* 대상 직무는 개발자(프론트엔드·백엔드·DevOps·앱·임베디드·AI·풀스택·게임)로 한정한다. 질문, 재료 점검, 문장 규칙이 개발자의 프로젝트·문제 해결·측정 기록을 기준으로 만들어져 있다.
* 사용자가 경험이 많지 않더라도 작은 프로젝트와 활동에서 의미 있는 경험을 발견할 수 있도록 한다.
* 사용자에게 하는 말(질문·안내·보고)과 포트폴리오 본문은 한국어로 쓴다. 사용자가 다른 언어를 요청할 때만 바꾼다. 기술 이름·코드·고유명사는 원래 표기를 쓴다.

## 목표 채용 시장

주요 사용자는 스타트업 취업을 목표로 한다.

따라서 대기업의 정형화된 스펙 나열보다 다음과 같은 정보를 중요하게 다룬다.

* 실제로 무엇을 만들었는가
* 어떤 문제를 발견했는가
* 문제를 어떻게 해결했는가
* 어떤 판단을 했는가
* 어떤 결과를 만들었는가
* 과정에서 무엇을 배웠는가
* 본인이 실제로 어떤 역할을 맡았는가

단순히 기술 스택이나 수상 경력을 나열하는 것보다 실제 경험과 문제 해결 과정을 보여주는 것을 우선한다.

## 포트폴리오 원칙

포트폴리오는 다음 질문에 답할 수 있어야 한다.

1. 이 사람은 무엇을 할 수 있는가?
2. 실제로 무엇을 만들어봤는가?
3. 문제를 발견하고 해결할 수 있는가?
4. 자신의 선택에 대해 설명할 수 있는가?
5. 팀에서 어떤 역할을 할 수 있는가?

### 우선순위

정보의 중요도는 다음 순서를 기본으로 한다.

1. 문제 해결 경험
2. 실제 결과와 성과
3. 본인의 역할과 기여
4. 의사결정과 기술적 판단
5. 프로젝트 설명
6. 기술 스택
7. 수상 및 기타 이력

## 디자인 방향성

포트폴리오는 단순히 "예쁜 디자인"을 목표로 하지 않는다.

사용자가 가진 경험의 핵심이 빠르게 전달되어야 한다.

특히 다음을 중요하게 생각한다.

* 명확한 정보 계층
* 강한 시각적 우선순위
* 핵심 성과의 강조
* 읽기 쉬운 타이포그래피
* 충분한 여백
* 페이지 간 일관성
* 프로젝트별 명확한 스토리

숫자나 성과가 존재한다면 본문에 묻히게 하지 않고 시각적으로 강조한다.

예:

53% 비용 절감
80.33% 응답 시간 개선
7,000+ → 1,000 tokens

단, 성과를 과장하거나 존재하지 않는 수치를 만들어서는 안 된다.

## 스타트업 채용 관점

스타트업 채용 환경을 고려한다.

스타트업에서는 지원자가 실제로 문제를 해결하고 제품을 만들어본 경험을 중요하게 보여줄 수 있어야 한다.

따라서 포트폴리오를 구성할 때 다음 구조를 우선적으로 고려한다.

문제
→ 원인
→ 판단
→ 해결
→ 결과
→ 배운 점

모든 프로젝트가 반드시 이 구조를 그대로 따라야 하는 것은 아니다.

사용자의 실제 경험에 따라 가장 자연스러운 구조를 선택한다.

## 중요한 것들

사용자가 제공하지 않은 경험, 성과, 기술, 숫자를 만들어내지 않는다.

사용자의 경험을 더 전문적으로 표현할 수는 있지만 사실관계를 변경하지 않는다.

학생이라는 이유로 경험을 과소평가하지 않는다.

작은 프로젝트라도 문제를 발견하고 직접 해결했다면 중요한 경험으로 표현할 수 있다.
