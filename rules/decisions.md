# 구조 결정 (rebuild, 2026-10-11)

하네스를 처음부터 다시 짠 기준. 사용자가 직접 정했다. 바꿀 때는 이 문서부터 고친다.

| 항목 | 결정 |
|---|---|
| 흐름 | 레퍼런스 질문 → (있음) 레퍼런스 분석 → 인터뷰 → PDF / (없음) 인터뷰 → 디자인 추천 → PDF |
| 레퍼런스 있음 | 레퍼런스를 분석해 구성 요소를 정리하고, 인터뷰에서 그 항목을 묻는다. 디자인은 레퍼런스를 따른다 |
| 디자인 추천 | 레퍼런스가 없을 때만, 인터뷰가 끝난 뒤 내용을 보고 AI가 시안 2~3개를 매번 새로 설계해 추천한다. 정해진 테마 없음 |
| 개인 정보 | 이름, 직무, 전화번호, 이메일, 링크, 한 줄 소개, 학력, 수상·자격증, 활동 |
| 프로젝트 목록 | 이름, 한 줄 소개, 팀 구성, 기간, 기술 스택, 링크 |
| 프로젝트 상세 | 맡은 역할과 수행한 작업. Notion·velog 등 다른 사이트 자료도 받는다 |
| 빈 곳 질문 | 상세를 받은 뒤 문제 해결 과정·수치 등이 비어 있으면 한 번만 묶어서 묻는다 |
| 링크·자료 | 열리지 않거나 읽을 수 없으면 그 턴에 사용자에게 알리고 확인을 부탁한다 |
| 말투 | 사용자에게는 존댓말(…해요). 포트폴리오 본문은 문어체 |
| 스킬 구성 | start(유일한 진입점) / interview / design / build |
| 재사용 | 기존 하네스에서는 PDF 생성만 가져왔다(make_pdf.py: HTML→PDF, 쪽 넘침·깨진 이미지 확인) |
| 검사 반복(loop) | 디자인·문장 검사 반복은 보류. 나중에 붙인다. 그때 수치 대조·말투·링크 검사도 같이 들인다 |
