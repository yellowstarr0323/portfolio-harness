# 디자인 (design)

**먼저 읽는다**: `../../rules/principles.md`의 "디자인 방향성".

## A. 레퍼런스 분석 (레퍼런스 있음, 인터뷰 전)

1. **사용자가 준 파일·URL만 연다.** 이미지·PDF는 Read(PDF는 모든 쪽), HTML은 소스를 읽는다. URL을 못 열면 interview "링크와 자료"처럼 바로 알리고 파일이나 스크린샷을 달라고 한다. 열지 못한 레퍼런스를 본 것처럼 정리하지 않는다.
2. `portfolio/reference.md`에 정리한다:

```markdown
# 레퍼런스 분석
- 출처: <경로나 URL>

## 쪽 구성
- 1쪽: <무엇이 어디에 어떤 크기로> (예: 위쪽 이름·직무 크게, 아래 연락처 한 줄, 오른쪽 사진)
- 프로젝트 쪽: <블록 순서와 배치>

## 디자인
- 색: #rrggbb … / 글꼴: … / 글자 크기: 제목 …, 본문 … / 여백·구분선·장식: …

## 인터뷰에서 받을 항목
- 개인 정보: (레퍼런스에 있는 칸만. 예: 이름, 직무, 이메일, GitHub, 자기소개, 기술 스택)
- 프로젝트 목록: (예: 이름, 기간, 한 줄 소개, 팀 구성, 기술 스택)
- 프로젝트 상세: (예: 역할, 주요 기능, 문제 해결, 성과)
```

3. 분석 결과를 3~5줄로 보여주고 바로 인터뷰로 간다. 레퍼런스를 따르므로 디자인 추천(B)은 하지 않는다.

## B. 디자인 추천 (레퍼런스 없음, 인터뷰 뒤)

1. 기록(`portfolio/profile.md`, `portfolio/projects/`)을 읽고 이 사람의 직무, 프로젝트 수, 강점(수치 성과가 많은지, 서비스 화면이 중요한지, 글 위주인지)을 파악한다.
2. **시안 2~3개를 새로 설계한다.** 정해진 테마는 없다. 시안마다 다음을 정하고, 서로 확실히 다르게 한다(색만 다른 같은 문서 금지):
   - 이름(예: "수치 강조형"), 이 사람에게 맞는 이유 한 줄
   - 배치: 1쪽 구성, 프로젝트 쪽 블록 배치(1단/2단, 이미지 위치)
   - 색(바탕은 흰색, 강조색 1~2개), 글꼴(한글 웹폰트), 제목 모양
3. 시안마다 **실제 내용으로 1쪽과 첫 프로젝트 쪽**을 `portfolio/design/<시안>/preview.html`에 만들고 PNG로 렌더한다:
   `python3 <이 스킬 디렉터리>/../build/scripts/make_pdf.py portfolio/design/<시안>/preview.html --png portfolio/design/<시안>/preview.png`
   PNG를 직접 열어 글자가 잘리거나 겹치지 않는지 확인하고, 깨진 시안은 고친다.
4. AskUserQuestion으로 고르게 한다. 선택지마다 이름·이유·미리보기 PNG 경로를 적는다. "직접 말할게요"(Other)로 조합 요청을 받으면 반영해서 다시 보여준다.
5. 고른 시안을 `portfolio/design.md`에 남긴다(색 값, 글꼴, 글자 크기, 배치, 미리보기 경로).

## 공통 원칙
- 읽기 쉬운 것이 먼저다: 본문 9~11pt, 캡션 8pt 이상, 글자와 바탕 대비가 충분할 것.
- 수치 성과는 본문에 묻히지 않게 크게 보여준다.
- 쪽마다 같은 역할의 글자는 같은 크기·모양으로.

## 끝나면
`portfolio/state.md`의 `design`과 `stage: build`를 적고 바로 build로 간다.
